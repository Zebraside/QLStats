Таблица всех игроков с засчитанными матчами: 9 колонок, сортировка на клиенте, липкий заголовок.

**Что передать.** `QLStats.PlayersTable(players, { sort, storageKey, loading, rows, label })`.
- `players` — массив из `GET /api/players` как есть. Порядок в API не гарантирован, сортирует таблица.
- `sort` — `{ key, dir }`, по умолчанию `{ key: 'kills', dir: 'desc' }`; `storageKey` — ключ `localStorage` для запоминания выбора.
- `loading: true` — настоящий заголовок и `rows` (8) строк-скелетонов, `aria-busy`.

**Колонки** — строго в этом порядке: Ник, Матчи, Убийства, Смерти, Лучший стрик, Победы, Средняя точность (%), Самоубийства, Смерти от окружения. Добавлять колонки (место, K/D и т.п.) нельзя.

**Поведение**
- Клик или Enter/Space по заголовку сортирует, повторный — меняет направление. Новая числовая колонка сначала сортируется по убыванию, ник — по алфавиту. Активная колонка: текст и стрелка `accent`, полоса снизу, `aria-sort`.
- `accuracy: null` («—») всегда внизу при любом направлении. При равенстве значений — по нику.
- Числа: mono, табличные цифры, по правому краю; точность — «31,8 %».
- Строка подсвечивается `surface-raised` при наведении и фокусе. Высота строки — `row-h` (36 px): 30–50 строк читаются без тесноты.
- Шире 66rem таблица во всю ширину, заголовок липнет к окну. Уже — таблица прокручивается в своей рамке в обе стороны (до 75vh), заголовок и колонка ника закреплены, у ника тень `shadow-sticky`.
- Ник обрезается многоточием (`nick-max`, в узком режиме `nick-max-narrow`), полный текст в `title`.
