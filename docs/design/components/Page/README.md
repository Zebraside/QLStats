Вся страница в варианте B «Пульт»: шаблон для index.html и app.js, собранный из шести компонентов.

**Раскладка.** Шапка: «QLStats», имя сервера (`server_title` из `/api/live`), справа UpdateIndicator. Под ней пульт: LiveMatch слева (5/12), справа «Статистика дня» и «За всё время» одна над другой, по три StatCard в ряд. Ниже на всю ширину — PlayersTable в секции «Игроки».

**Что передать.** `QLStats.Page({ live, liveLoading, liveReceivedAt, summary, players, status, storageKey, onRetry })`. `summary` и `players` — последние успешно полученные ответы; при ошибке API их не обнулять, а передавать `status: { status: 'error', retryAt }`. Если данных ещё не было совсем — `summary: null, players: null`, тогда вместо сводок выводится `EmptyState kind="error"`, а таблица не показывается.

**Ширина.** Раскладка подстраивается под ширину `.qs-app` (container queries), поэтому при масштабе 200 % и на телефоне ведёт себя одинаково:
- от 70rem (1120 px) — пульт в две колонки;
- уже 70rem — одна колонка в порядке брифа, ростер LiveMatch снова в две колонки;
- уже 46rem — карточки по одной в ряд;
- уже 40rem — поля 16 px, UpdateIndicator уходит под название.

**Правила**
- При 12 участниках LiveMatch раскладывает ростер в две колонки и остаётся вровень с колонкой сводок. Длинные ники при этом обрезаются раньше, полный текст в `title`.
- Таблица шире 66rem идёт во всю ширину, и её заголовок липнет к окну; уже — прокручивается в своей рамке.
- Обновление: LiveMatch — раз в 5 с, сводки и таблица — раз в 30 с и при возвращении на вкладку; заменяется только изменившийся блок (ETag/304), страница целиком не перерисовывается.
